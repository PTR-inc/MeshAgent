OpenSSL static library state
============================

Target version: openssl-1.1.1w (11 Sep 2023) - the last public 1.1.1 release.
  sha256: cf3098950cb4d853ad95c0841f1f9c6d3dc102dccfcacd521d93925208b76ac8
  Use ./linux/fetch-openssl to download and verify the source tarball.

NOTE: 1.1.1 is end-of-life (11 Sep 2023) and receives no further public fixes.
1.1.1w is an interim step to close the CVEs published while 1.1.1 was still
supported. Migration to 3.5 LTS is tracked separately.

Two build paths exist for these archives:
  1. The `openssl/libstatic/linux/openssl-<arch>` scripts in this directory -
     portable, no external dependency, but only cover the toolchains an apt
     Debian/Ubuntu box has natively (glibc cross-compilers + native gcc/gcc -m32).
  2. `openssl/libstatic/build/` (env.sh/targets.sh/build.sh/verify.sh,
     git-tracked). Covers everything path 1 does plus musl/uClibc OpenWrt
     SDKs, bootlin toolchains, BSD clang cross-sysroots, osxcross macOS
     cross-builds, and dd-wrt-archive toolchains. Toolchain/sysroot/download
     data stays outside the repo, at `$BUILDROOT` (default `/opt/buildroot`).
     `provision-buildroot.sh` (repo root - it also wires two toolchains the
     makefile needs to cross-compile the agent itself) fetches and extracts
     everything with a public URL into `$BUILDROOT`, including dd-wrt's
     toolchain archive now (checksum-verified where a checksum is published;
     dd-wrt and the OpenWrt SDKs don't publish one); only osxcross remains
     bring-your-own. `targets.sh` is the authoritative flag/T_OBJS list for
     path-2 targets.

Configure flags are otherwise identical for every target (only the -O level
and the Configure target name differ). asm is enabled (no `-no-asm`) wherever
OpenSSL has a per-arch Configure target with genuine runtime capability-gated
asm:
  - x86/x86-64 family (CPUID -> OPENSSL_ia32cap_P): x86-64, x86, alpine-x86-64,
    openwrt_x86_64, freebsd, openbsd.
  - AArch64 (getauxval(AT_HWCAP) -> crypto/armcap.c): arm64, aarch64,
    aarch64-cortex-a53.
  - 32-bit ARM (linux-armv4 Configure: armhf, armhf2, linux-armada370-hf) is
    DELIBERATELY LEFT AT -no-asm: asm here produced WRONG crypto results
    under qemu-arm (non-deterministic SHA-384/512 hashes, RSA.verify()
    rejecting its own fresh signature). Reverting to -no-asm did not fix it -
    the bug is unrelated to asm, unresolved, HIGH severity. Do not trust ANY
    RSA or SHA-384/512 operation on these three targets, asm or not.
  - Everything Configured as `linux-generic32`/`linux-generic64` (arm,
    arm-linaro, pogo, poky, poky64) has NO asm modules to enable regardless
    of the flag.
  - MIPS (`mips`/`mipsel`, linux-mips32) has no runtime capability fallback
    - asm is compiled unconditionally for the Configure-time ISA. Only
    trusted here after a real crypto run (`speed aes-128-cbc sha256` under
    qemu-mipsel).

Every 64-bit Configure target gets `enable-ec_nistp_64_gcc_128` (faster P-256
ECC via native 128-bit ints), matching the repo's own `openssl-<arch>`
scripts. The flag doesn't add a separate object file.

`-Os` is applied only to genuinely IoT/router/flash-space-constrained
targets, not simply "everything cross-compiled". General-purpose 64-bit
targets that happen to be built cross/emulated but aren't actually
space-constrained (arm64, alpine-x86-64, freebsd, openbsd) favor speed
instead, same as x86-64/x86. Per-target -Os status is called out below.

See the per-arch `openssl-*` scripts (path 1) or `targets.sh` (path 2) for
the exact flag list actually used per target.

Rebuilding
----------
CI: .github/workflows/build-openssl-libs.yml (workflow_dispatch) builds the
targets reachable from GitHub runners and uploads them staged in this repo's
directory layout.

Manual, path 1 (portable, glibc-only): ./linux/fetch-openssl, then run the
matching openssl-<arch> script from inside the extracted source directory.

Manual, path 2 (musl/uClibc/BSD/dd-wrt/macOS targets, any machine with
$BUILDROOT provisioned):
  ./provision-buildroot.sh                      # first time only: fill $BUILDROOT
  openssl/libstatic/build/build.sh <target|all>
REPO is auto-derived from the script's own location (override with REPO=...
to stage into a different checkout). Verifies version+object-count+glibc-
symbol before staging; rejects and stages nothing on any mismatch. Before
running `build.sh all` (or any target whose targets.sh entry doesn't
obviously match this repo's own openssl-<arch> recipe for the same dir),
diff the two - a mismatched Configure target or missing asm override there
will silently overwrite a better archive with a worse one.
